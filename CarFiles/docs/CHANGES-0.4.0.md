# 0.4.0 — переработка трансляции и интерфейса

## Почему картинка шла «через раз» (найдено в коде 0.3.2)

| # | Причина | Что было | Что стало |
|---|---------|----------|-----------|
| 1 | Потерянный последний кадр | Кадры чаще 250 мс отбрасывались; если экран потом замирал, на машине оставался старый кадр | `FrameThrottle`: кадр копируется всегда, кодирование с «хвостом» — последнее состояние всегда уходит |
| 2 | Нет первого кадра на статичном экране | Машина ждала до первого изменения экрана | Watchdog через 1,5 с пере-подключает поверхность (до 3 раз) |
| 3 | Порт 8787 занят | Быстрый стоп/старт → `BindException` → «Не удалось начать трансляцию» | `SO_REUSEADDR`, перебор портов 8787–8797 |
| 4 | Опрос `frame.jpg` | Новое TCP-соединение на каждый кадр, пул из 2 потоков, очередь 8 — подвисшие клиенты блокировали остальных | Один MJPEG-поток `stream.mjpg` + heartbeat, кэшируемый пул, вытеснение самого старого клиента |
| 5 | Оборванные клиенты | Слот освобождался только при ошибке записи | Проверка обрыва на каждом цикле (≤ 0,4 с) |
| 6 | Опрос на машине | `Handler` каждые 300 мс + сравнение ссылок | Подписка на кадры (`addListener`), декодируется только самый свежий, показывается кадр, уже бывший до открытия экрана |
| 7 | GC | Новый `Bitmap` на каждый кадр | Один переиспользуемый буфер и `ByteArrayOutputStream` |
| 8 | Размер/поворот | Размер из `displayMetrics`, нечётные размеры | `currentWindowMetrics`, чётные размеры, пересоздание `ImageReader` при повороте |
| 9 | Уведомление | `POST_NOTIFICATIONS` не запрашивался (Android 13+) | Запрашивается перед стартом |

Невозможно проверить без машины и телефона: появляется ли наш экран в списке Android Auto 17.x. Для этого добавлен
журнал событий (сервис создан → host подключился → экран создан → экран виден → кадр показан), он виден в «Диагностике»
и в «Трансляции экрана».

## Интерфейс
Единая тёмная тема (`Ui.kt`), главный экран-«хаб» с плитками, отдельная «Медиатека», новый экран трансляции
(статус, fps/размер, живое превью, состояние автомобильного экрана, адрес потока), диагностика с журналом.

## Проверено
- `FrameServerTest` — 8 JUnit-тестов с настоящими сокетами (MJPEG, heartbeat, 20 быстрых переподключений,
  занятый порт, неверный ключ, троттлинг с хвостом). Запущены на JVM, 3 прогона подряд — OK.
- Не проверено: сборка Gradle/AGP, Kotlin-слой Android (Activity/Service), lint, работа на телефоне/в машине —
  в среде разработки не было Android SDK и доступа к Google Maven.
