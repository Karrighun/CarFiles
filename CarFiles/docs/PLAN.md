# План разработки CarFiles

## Цель и ключевое решение

Сделать приложение для доступа к своим файлам в машине. Приоритет — устойчивое чтение файлов, воспроизведение, управление с магнитолы, диагностика. Простой интерфейс с крупными элементами.

Android Auto (проекция с телефона), Android Automotive OS (приложение в ОС автомобиля) и обычная Android-магнитола — разные цели. Основная цель здесь Android Auto; локальный просмотр на телефоне нужен для настройки и проверки ядра.

## Что выяснено о конкуренте

GitHub содержит README и изображения, не код. Сайт рекламирует локальное видео, IPTV и другие медиамодули; README дополнительно описывает галерею и файловый менеджер. Механизм вывода собственного интерфейса в Android Auto не раскрыт. Нельзя заключить по маркетинговой странице, что это публичный стабильный API. Установка через закрытый трек Google Play не является доказательством доступности видео API или прохождения общедоступной публикации.

Есть расхождение Android 5+ на сайте против Android 11–17 в README. Совместимость, доступность приложения и технические обещания конкурента на реальном оборудовании нами не проверены.

Официальная документация Google на 31.10.2026 допускает аудиокаталог Android Auto через MediaSession и MediaLibraryService. Для parked-приложений Android Auto сейчас перечислены игры; видео относится к Android Automotive OS. Следовательно, простое добавление CAR_LAUNCHER не решает задачу видео/галереи в Android Auto.

## Этап 0. Проверить путь к экрану машины — 2–4 рабочих дня

1. Зафиксировать телефон, версию Android/Android Auto, модель магнитолы, проводное/беспроводное подключение и канал установки конкурента.
2. На доступном устройстве проверить реальное поведение конкурента: запуск, локальные файлы, потеря соединения, остановка, повторный запуск. Покупка/запрос приглашения не выполнялись.
3. Протестировать официальный MediaLibraryService в DHU и на магнитоле; отдельно проверить актуальный статус parked-video API и треков распространения.
4. Подготовить техническое решение для видео: официальный Android Auto API, если станет доступен; отдельный AAOS вариант; либо документированная исследовательская интеграция с известными ограничениями совместимости.

Критерий выхода: воспроизводимая демонстрация вывода тестового видео именно в целевой машине либо зафиксированное отсутствие поддерживаемого пути. До этого нельзя обещать паритет с конкурентом. Произвольные activity не маркируются как игры ради появления в лаунчере.

## Этап 1. Локальное ядро — начато, 3–5 дней до проверенного MVP

Уже написаны: Gradle-проект, файловый доступ SAF, браузер папок, локальные видео/изображения, аудиосервис Media3, базовый аудиокаталог Android Auto, тест классификации и CI.

Осталось: первая сборка и устранение ошибок; тесты жизненного цикла; понятные ошибки доступа и кодеков; выбор нескольких папок; подтверждение работы аудиофокуса и фонового сервиса на Android 11–16/17.

Критерий выхода: APK успешно проходит сборку/lint; папка остаётся доступной после перезапуска; локальные файлы открываются без интернета; завершение Activity освобождает видео; автомобиль показывает и воспроизводит аудио.

## Этап 2. Надёжная медиатека — 4–7 дней

Room-индекс по URI, индексирование WorkManager, отмена сканирования, лимиты и диагностика облачных провайдеров. Иерархический аудиокаталог, notifyChildrenChanged после обновлений. Плейлисты, очередь, next/previous, shuffle/repeat, постоянная позиция, восстановление после завершения процесса. Проверки USB disconnect и отзыва разрешений. Ограничить команды и подключения контроллеров в соответствии с официальной моделью доверия, сохранив совместимость Android Auto.

Критерий выхода: 10000 файлов без блокировки интерфейса; корректное изменение библиотеки; отсутствие произвольного воспроизведения URI через экспортированный сервис; восстановление состояния.

## Этап 3. Видео на экране автомобиля — оценка после этапа 0

Изолировать транспорт/автомобильную поверхность от файлового ядра. Для поддерживаемого пути реализовать адаптивный экран, обработку состояния парковки/жизненного цикла, переподключение и корректное освобождение поверхности. При отсутствии официального пути результат этапа — проверенное ограничение, а не фиктивный сервис с обещанием видео.

Для AAOS понадобится отдельный модуль/вариант, конфигурация автомобильного приложения и интеграция ограничений UX; в текущем проекте этого нет.

Критерий выхода: демонстрация на конкретном телефоне и магнитоле, включая переподключение, звонок и смену ориентации/разрешения. Работа на одной конфигурации не означает поддержку всех машин.

## Этап 4. Другие файлы и сети — 5–10 дней

Добавить ограниченный просмотр UTF-8 текста и PDF, затем галерею/слайдшоу. Документы Office открывать через поддерживаемый обработчик либо отдельный конвертер после выбора требований. Затем HTTPS-потоки и M3U/HLS, ограничения размеров плейлистов, обработка тайм-аутов. Сетевые источники — только пользовательские/разрешённые. YouTube оценивать отдельно по официальным API и условиям платформы; извлечение потоков не считать надёжной основой.

## Этап 5. Подготовка релиза — 3–5 дней

Долгие сессии, память/нагрев, журнал ошибок без имён личных файлов, политика конфиденциальности, подпись и защищённое хранение ключей, закрытое тестирование, требования категории Google Play. Аналитика и лицензирование для начального MVP не нужны.

## Матрица приёмки

| Сценарий | Ожидаемый результат |
|---|---|
| Android 11 / 13 / 15 / актуальная версия | установка, SAF, foreground audio без сбоев |
| MP3/FLAC, MP4 H.264/AAC, JPG/PNG | базовое чтение; другие кодеки проверяются отдельно |
| Пустая папка / потеря разрешения / отключение USB | ясная ошибка, приложение продолжает работать |
| Большая папка / облачный провайдер | нет зависания UI, лимиты и отмена |
| Звонок / другое аудиоприложение / снятие наушников | корректная пауза/потеря фокуса |
| DHU 800×480, широкий и портретный экран | корректный штатный аудиокаталог |
| Проводное и беспроводное подключение | восстановление сеанса и управления |
| Кнопки руля / поворотный контроллер | поддерживаемые команды выполняются |
| Смена папки во время работы | старые запросы не подменяют новый каталог |
| Видео на автомобильном экране | проверяется отдельно после выбора поддерживаемого транспорта |

Ориентир: 2–4 недели для устойчивого локального ядра и аудио Android Auto одним разработчиком. Паритет видео с закрытым конкурентом отдельно не оценён до технического исследования; перечисленные сроки — оценки, не гарантия.

## Результат первой сборки

31.10.2026: APK собран, 4 unit-теста прошли, lint: 0 ошибок, 11 предупреждений. Добавлен Wrapper. Исправлены вложенные SAF-папки и корень подписки каталога; добавлены голосовой запуск по имени файла и проверка подключения контроллеров. На Android-устройстве ещё не запускалось.

Исследование [RESEARCH.md](RESEARCH.md) выявило отдельный механизм проекции в Fermata/CarStream. Следующая задача — минимальный projection-lab с проверкой SDK, условий распространения и совместимости. В текущем APK видео в Android Auto отсутствует.

Целевая связка: Samsung S24 FE + GAC GS8 2026, USB и wireless. См. [сценарий испытаний](DEVICE-TEST.md).
